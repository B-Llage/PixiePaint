# Pixie Paint architecture

## Runtime and entry point

This is a client-side pixel art editor built with Next.js App Router, React, TypeScript, and Tailwind CSS. `app/page.tsx` mounts `PixelPencil` inside `PixelPencilSettingsProvider`. `app/layout.tsx` supplies metadata, global CSS, and analytics. The stylesheet uses system fonts, so production builds do not fetch font assets. The editor is always dark: `app/layout.tsx` puts a `dark` class on `<html>` and `app/globals.css` redefines Tailwind's `dark:` variant to follow that class instead of `prefers-color-scheme`, so the `light`/`dark:` class pairs in components never split by system scheme. There is no application backend or server persistence.

## Editor state and data flow

`PixelPencil.tsx` owns the current tool, palette, layers, selection, pointer gestures, undo/redo, viewport, and dialogs. Layers are ordered bottom to top. Each layer's pixels are a `PixelBuffer` (`pixel-buffer.ts`): a `Uint32Array` of `gridWidth * gridHeight` packed RGBA values in ImageData byte order, where `EMPTY_PIXEL` (0) is never painted and `TRANSPARENT_PIXEL` is explicit transparent paint. `pixel-buffer.ts` holds the pure buffer operations (pack/unpack between hex strings and packed values, cell and mask fills that return the rect they changed, rect extract/write/copy, translation, resize, and `composeInto`, which flattens visible layers inside a rect so the topmost painted pixel wins). `pixel-operations.ts` keeps selection cloning and equality and layer naming. `grid-geometry.ts` holds the pure grid algorithms: brush footprints and their bounds, Bresenham lines, square/circle/triangle rasterization with the perimeter pass for unfilled shapes, stroke resampling between world-space pointer samples, canvas-sized cell masks with their bounds, and `collectFillMask`, the scanline flood fill shared by the bucket tool and its hover preview. These modules take the grid size explicitly; `PixelPencil` keeps thin `useCallback` wrappers around them so hook dependencies stay stable.

Layers, the active layer id, and the selection are held with `hooks/useStateWithRef.ts`, which pairs each React state value with a ref and exposes one setter that writes the ref synchronously before scheduling the render. Pointer and keyboard handlers are registered once and read the current value through those refs instead of re-subscribing on every change; functional updates passed to these setters run immediately against the ref, so a caller can read flags set inside the updater. Pointer gesture bookkeeping lives in plain refs because it is never rendered.

Layer buffers are mutated in place, and every pixel write goes through `PixelPencil`'s `editLayer(layerId, rect, mutate)` (typed in `layer-edit.ts`): it records the history tiles under `rect` first, runs `mutate` on the layer's buffer, and when `mutate` returns the rect it changed, recomposites that rect, bumps the `layerVersion` state. It never bumps `previewVersion` itself: `capturePixelsBefore` always opens a history action, so thumbnails update through the `finalizeAction` wrapper and through structure changes (see the comment near `editLayer` in `PixelPencil.tsx`). Each edit is bounded by the area it touches, never the whole layer. `hooks/useComposite.ts` owns the flattened composite buffer: `recompose(rect)` recomposes only that rect and bumps `compositeVersion`, a grid-size change gives the composite a new buffer that is composed in full in an effect, and `hooks/useRedrawSignal.ts` coalesces redraw requests into one animation frame. `PixelPencil` passes the composite buffer, its version, and its dirty rect straight to `PixelGrid`.

`hooks/useEditorHistory.ts` owns undo/redo as patches: a pixel action keeps the before and after bytes of each 64x64 tile it touched on one layer, while layer-list changes (`recordStructureChange`) keep whole buffers only for layers they removed or replaced, such as a deleted layer or every layer on Clear. `PixelPencil` hands it `captureMeta` (layer ids, names, visibility, active layer id, selection), `applyMeta` (rebuilds the layer list in the recorded order from the live buffers plus any returned ones, creating a blank buffer for a layer that no longer exists, restores the active layer and selection, and recomposes in full only when the layer stack itself changed), `getLayerBuffer`, and `onPixelsRestored`, which recomposes each tile undo or redo writes back. Strokes, fills, and drags run between `beginAction` (or the first capture) and `finalizeAction`; `PixelPencil`'s `finalizeAction` wrapper also bumps `previewVersion`, and its `recordStructureChange` wrapper recomposes and bumps both versions. The undo stack is capped by entry count and a byte budget. A cancelled move drag restores the stacks it saved before starting, and a grid resize clears history.

When the `gridWidth`/`gridHeight` settings change, `PixelPencil` migrates the artwork during the render that first sees the new size (React's adjust-state-during-render pattern, tracked by a `layerDimensions` state) rather than in an effect, so no frame renders the layers against the wrong dimensions: each layer's buffer is copied with `resizeBuffer` (top-left anchored, cells outside the new grid dropped, new cells empty), history is cleared (which also ends any open action), and an effect keyed on `layerDimensions` drops everything else laid out for the old grid because render may not write refs: it cancels an active move drag (`cancelActiveDrag`, which releases capture and writes nothing back, since the drag's copies are old-size), resets the stroke pipeline (`resetForGrid`: drawing flags, applied set, pointer queue and the three canvas-sized masks, which reallocate lazily), clears the hover cell and path preview, and requests a redraw. Grid width and height are any integer from 1 to 2048 (`clampGridDimension` in the settings context; the settings modal edits them with `GridDimensionInput`).

`hooks/useLayerPreviews.ts` owns the layer thumbnails shown in the layers panel: it rasterizes every layer in a requestAnimationFrame callback (one `putImageData` of an `ImageData` over the layer's own buffer into a reusable grid-sized offscreen canvas, then one `drawImage` over the checkerboard into the thumbnail, hidden layers at 0.4 alpha, with no per-cell loop; grids up to 64 cells use a whole-number nearest-neighbor upscale, while larger grids are halved with high-quality smoothing through a reusable scratch canvas until within 2x of the thumbnail and then drawn smoothed into it, so sparse art stays visible) after the layers, grid size, or `previewVersion` change (in-place edits do not change the layers array, so `previewVersion` is how thumbnails catch up) and returns a map keyed by layer id that only holds entries for layers that still exist, so an empty grid yields no previews without any effect writing state.

`hooks/useSelection.ts` holds the rectangular selection in two hooks: `useSelectionState` owns the selection (its `data` is the rect's packed cells, row-major), its preview rect, the pointer-gesture bookkeeping, and the helpers (rect normalization, offset clamping, capturing a rect's cells with off-grid cells empty, and writing or erasing the selection's non-empty cells through one `editLayer` call clipped to the grid), and exposes `restoreSelection` for history; `useSelectionGestures` wires the rect-select pointer gestures, the Delete/Escape/select-all keys, and the outside-click cancel to those helpers and to history's `beginAction`/`finalizeAction`. The split exists because history metadata reads the selection while the gestures open history actions.

`hooks/useMoveDrag.ts` owns the move tool's drag: it picks the layer (the active one, or with auto-pick the topmost visible opaque layer under the pointer), copies it once at pointer-down (with any floating selection stamped in), and on each step writes that copy, shifted by the drag delta (`copyShiftedRect`), over only the union of the pixels' original, previous, and current bounds through `editLayer`, so a step costs that union rather than the canvas. It opens the history action only once the pointer has moved a cell, and on cancel or an unchanged drag writes the original back over those bounds and restores the selection and the history stacks it saved.

`hooks/useLayerOperations.ts` owns the layer panel's operations (create, delete, rename, toggle visibility, reorder, select); each structural change runs inside one `recordStructureChange` call (delete hands the removed buffer to history), and the ones that change the active layer drop the hover cell and path preview.

`hooks/useStrokePipeline.ts` owns freehand drawing for the pencil and eraser and the brush helpers the line and shape tools share: the brush footprint, single-cell painting bounded by the brush square, path painting that stamps every footprint into a reused scratch mask and fills it in one edit, the pointer-sample queue traced once per animation frame, a canvas-sized stroke mask that grows by only the footprints of newly crossed cells (it is also the path preview, grown in place, and is committed as one edit over its bounds and then cleared over them when the stroke ends), the captured pointer, and the window pointer-move listener that keeps tracing outside the canvas.

The picker reads the composite, so it returns lowercase hex; palette swatches match the active color case-insensitively and mark it `aria-pressed`. Selection can float while being moved before it is committed. Pointer events are converted from viewport coordinates to grid cells in `PixelPencil`, then dispatched to the active tool.

The hovered cell (`hoverRef`), the path preview (`pathPreviewRef`, a `PreviewMask` built in a scratch mask that the stroke pipeline clears over its previous bounds), and the stroke's draw value (`drawValueRef`) are refs: writing them requests a redraw through the redraw signal instead of re-rendering the editor, so pointer movement does not re-render the panels. `getOverlayFrame` reads those refs when the grid draws and returns the frame's preview masks (brush footprint and brush-size shadow stamped into reusable scratch masks, the bucket's fill region cached per `layerVersion`, reused for any hovered cell inside the cached region, and skipped while drawing) with the path and hover colors and the dim setting.

`PalettePanel` shows preset colors and the selected color's hue, saturation, and lightness sliders. `SelectedColor` converts between hex and HSL, keeps the last custom HSL selection so hue survives grayscale and lightness extremes, and updates both the active color and the drawing value when a slider changes.

On mobile, a fixed-height Layers/Palette control row opens one panel at a time as a bottom sheet over the canvas viewport. The sheet occupies no layout height, so opening it does not change the measured viewport or the artwork's display cell size. Its contents scroll within the sheet, and the uncovered canvas remains interactive. At the desktop breakpoint, the controls move to the sidebar.

`PixelGrid.tsx` draws on an HTML canvas in passes implemented as pure helpers in `grid-renderer.ts`, each bounded by the visible cells: the checkerboard as one fill with a `CanvasPattern` aligned to the artwork, whose tile is built at the real device-pixel checker size once per zoom level and never scaled (Safari interpolates scaled patterns), falling back to one `fillRect` per visible checker at fractional checker sizes or tiles over 2048 px, or, when that would exceed 4096 fills (such as the fit zoom of a large grid), to one nearest-neighbor `drawImage` of a cached one-pixel-per-cell checkerboard bitmap; the composite as one nearest-neighbor `drawImage` of the visible cells from an offscreen canvas the size of the artwork, whose `ImageData` shares the composite buffer's memory and receives only the dirty rect through `putImageData` (a new buffer or a version change without a dirty rect uploads everything unless a redraw frame already consumed that recompose's rect, and a frame whose buffer size disagrees with the grid skips the blit); the overlay as one `ImageData` over the union of the preview masks' bounds within the visible cells, scaled over the artwork; grid lines when cells are at least 4 px; and a floating selection blitted from its packed cells at its offset, with its outline still a DOM element. The outline elements are clipped to the viewport (plus a few pixels of margin, with the dash phase kept anchored to the selection's real corner), so a whole-canvas selection on a large grid stays cheap to animate. Cell edges are snapped to device pixels with the same rounding everywhere so adjacent cells share edges. The grid draws in an effect when the composite, geometry, settings, selection, or `getOverlayFrame` change, and again on each redraw-signal notification, at most once per animation frame. `hooks/useCanvasViewport.ts` owns the viewport: it measures the space available to the grid, derives the display cell size (the persisted cell size, limited by that space and a mobile or desktop minimum, times the zoom scale), the zoom floor, the artwork's centered render offset when it fits, and the signed pan offset, and it converts client points to fractional artwork cells. The grid applies the offset to artwork rendering and pointer hit testing. `canvas-pan.ts` computes shared pan bounds that keep at least 216 pixels of artwork visible on each axis (or its full size or the viewport size if smaller); the hook clamps the stored offset to those bounds on read. Magnifier clicks, touchpad pinch, identifiable mouse-wheel notches, and Cmd/Win + wheel zoom around the cursor's fractional artwork position, adjusting the viewport offset so the same point remains under the cursor. Chromium pinch arrives as Ctrl + wheel; Safari uses gesture events. Ambiguous pixel-mode scrolling keeps the two-finger pan behavior because wheel events do not reliably identify the input device. Zoom steps are whole multiples above 1x and halvings below it. `canvas-zoom.ts` computes the floor as the scale at which the whole artwork fits the measured viewport (1 when it already fits), so any grid can be seen in full on any viewport; the hook raises a stored zoom below a newly larger floor, and reaching the floor centers the artwork instead of keeping the cursor anchor. A zoom may extend the pan range beyond the usual visibility limit to preserve that anchor; the hook keeps that exception until the viewport, cell size, or grid size changes. Scrollbar thumbs reflect the extended range; two-finger scrolling and middle-button panning can move back toward the usual limit but cannot move farther past the zoom-created offset. `LayersPanel`, `Toolbox`, `ToolSettingsPanel`, and the modal components are controls around this editor state; `hooks/useEditorDialogs.ts` holds the open state of the reset, settings, changelog and hotkeys dialogs and closes the open one on Escape, while the save dialog belongs to `usePixelExport`. The selection outline styles live in `app/globals.css`. `PixelPencilTools.ts` defines each tool and the ordered `TOOLS` list; the toolbar, hotkey handling, and the Hotkeys dialog all derive from it.

Stroke path previews render at full opacity by default so in-progress paint shows its final color. Brush and bucket hover previews also show the selected color at full opacity; eraser and transparent paint previews show the checkerboard. The persisted `dimStrokePreview` setting restores the former translucent path preview and hover shading. The brush-size shadow retains its own preview style.

The brush size input keeps focus during typing. `PixelPencil` ignores the first canvas pointer gesture after typing so that gesture only dismisses the field. A vertical drag on the size input clears focus as it adjusts the size, allowing canvas keyboard shortcuts immediately afterward.
During that drag, `PixelPencil` computes the active brush footprint at the center of the visible artwork. `PixelGrid` draws it as a translucent shadow above the artwork without changing pixels, then removes it on pointer release or cancel.

## Performance budget

The editor must stay responsive on a 2048×2048 canvas. Desktop browsers are the target; phones are best effort. Read this section before touching the pixel model, renderer, history, or tools.

Design principles:

1. **Per-frame work is bounded by the viewport**, never by the number of canvas cells. One frame draws the visible region of a prebuilt bitmap and an overlay whose cost is proportional to the preview and selection areas.
2. **Per-input work is bounded by the touched area.** A stroke step, fill, move step, or undo touches the cells it changes and the dirty rectangle around them, never the whole layer.
3. **No whole-layer scans in a hot path.** Equality checks, clones, and compares of full layers are allowed only in one-shot operations such as resize and reset, and even there they run once.
4. **Pixel storage is typed arrays**, so a layer costs 4 bytes per cell and copies are `TypedArray.set` calls.
5. **Hover and preview state do not flow through React.** They live in refs and redraw the canvas directly.

Rules that follow from them:

- **Dirty-rectangle contract.** Every pixel write goes through `editLayer(layerId, rect, mutate)`. The caller passes the bounding rect of what it may change before mutating, so history can capture the tiles under it first. `mutate` returns the rect it actually changed (or `null`), and only that rect is recomposed and uploaded. Tool code must write layer pixels through `editLayer`. The sanctioned exceptions are history restore (`writeRect` via `onPixelsRestored`), Clear (`data.fill` inside `recordStructureChange`), and grid resize (`resizeBuffer`). Do not pass a whole-canvas rect from a per-pointer path.
- **Viewport-bound frames.** `PixelGrid` draws only the visible cells each frame: the checkerboard as one pattern fill (or one scaled bitmap draw at fractional zoom on large grids), the composite as one `drawImage` of the visible cells, the overlay as one `ImageData` over the visible part of the preview bounds, and no per-cell DOM calls. The overlay's brush-size shadow edges and floating-selection transparent tiles still use per-cell `fillRect`, bounded by the visible area.
- **Grid lines** are drawn only when cells are at least 4 px, so a zoomed-out large canvas never pays for them.
- **Benchmarks.** `npm run bench` (Vitest bench over `perf-scenarios.ts`, pure modules only) reports a 200-step stroke, a bucket fill of an empty canvas, a 100-cell translate step, a 64×64 recompose, and a stroke undo and redo at 256, 1024, and 2048. It measures the pure modules only (mask build, fill, shift, recompose, tile replay) and excludes history tile capture and the editor's recompose, so its numbers understate the user-visible commit cost. It is informational and not part of `npm run check`; run it before and after changes to these paths and report the numbers.

## Browser state and export

`PixelPencilSettingsContext.tsx` owns display and canvas settings. It hydrates validated values from the `pixel-pencil-settings` localStorage key after mount, then writes changes back. Artwork itself is in memory and is lost on reload unless exported.

The persisted `useToolAsMousePointer` setting is off by default. When enabled, `PixelPencil` passes the selected tool's 32×32 cursor icon and per-tool click point to `PixelGrid`, which applies them as a CSS cursor only on the canvas. These cursor icons are nearest-neighbor enlargements of the 16×16 toolbar icons. The pointer graphic is separate from canvas rendering and PNG export.

`usePixelExport.ts` uploads the composite buffer once with `putImageData` into a grid-sized canvas, blits it with one nearest-neighbor `drawImage` into the output canvas at the chosen scale (empty and transparent cells carry alpha 0, so they stay transparent), and downloads a PNG through a blob URL. Its open dialog's preview is drawn on the animation frame after the dialog opens, the scale changes, or the composite changes, so render never reads the composite ref. The preview goes through the same composite, `putImageData`, `drawImage` path but at a bounded scale (`min(exportScale, floor(MAX_EXPORT_PREVIEW_DIMENSION / longest side))`, at least 1, with `MAX_EXPORT_PREVIEW_DIMENSION` = 1024), while only `confirmSave` renders the full `exportScale`; if the save canvas has no 2D context, nothing downloads and `saveError` is set until the dialog closes or the scale changes. It also returns `availableScales`, the export scales whose output stays within `MAX_EXPORT_DIMENSION` (16384) pixels on both axes (always including 1), which the dialog renders; a grid-size change clears the selected scale back to 1 using the adjust-state-during-render pattern (a `scalesForSize` state beside the selection), so a scale hidden by a resize does not resurface when the grid shrinks again, and the effective scale is also derived as 1 whenever the selection is unavailable. Static tool icons and the logo live under `public/`.

## Verification

Run `npm run check` for lint, type checking, and Vitest. Run `npm run bench` for the hot-path timings described in the Performance budget. Tests sit beside the code they exercise. GitHub Actions runs the same gate for pull requests and `main`. On `main`, a release job then tags and publishes a GitHub Release for the package version if that tag does not exist yet, with notes rendered from `app/changelog.json` by `scripts/release-notes.mjs`.
